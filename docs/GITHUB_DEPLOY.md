# رفع سمارت كاش على GitHub وتشغيله

## 1) ماذا يوجد في المستودع
- `prototype/` المصدر (HTML و JS). فيه البيانات التجريبية للشرح.
- `app/build.py` يبني النسخة الإنتاجية في `dist/` **بدون أي بيانات افتراضية** (يضيف `window.SC_PROD=1`).
- `.github/workflows/pages.yml` يبني وينشر `dist/` تلقائيًا على GitHub Pages عند كل دفع إلى `main`.
- `db/` مخطط PostgreSQL للمرحلة القادمة (خادم ومزامنة)، `docs/` التصميم والمعمارية.

## 2) الرفع خطوة بخطوة
1. أنشئ مستودعًا فارغًا على github.com باسم `smart-cash` (بدون README).
2. فك ضغط `smart-cash-repo.zip` وافتح الطرفية داخل المجلد `smart-cash`:
```
git remote add origin https://github.com/اسمك/smart-cash.git
git push -u origin main
```
3. في المستودع: Settings ثم Pages ثم Source ثم **GitHub Actions**.
4. افتح تبويب Actions وتأكد أن "Deploy Smart Cash to GitHub Pages" نجح (علامة خضراء).
5. الرابط: `https://اسمك.github.io/smart-cash/`. افتحه على الجوال ثم ثبّته (أندرويد: تثبيت التطبيق، آيفون: مشاركة ثم إضافة إلى الشاشة الرئيسية).

الخطة المجانية تتطلب مستودعًا **عامًا** لـ Pages. احذف رقم الدعم والبريد من `prototype/js/pay.js` قبل ذلك إن لم ترد نشرهما.

## 3) أول تشغيل: الحسابات والمستخدمون
1. اختر الخطة (أفراد / مؤسسة صغيرة / شركة كبرى) ثم **أنشئ مساحة عملك**: اسم المؤسسة، اسمك، بريدك، كلمة مرور (8 أحرف على الأقل، حروف وأرقام).
2. يُنشأ حساب المالك (أو مدير النظام في الشركة الكبرى) ويدخل مباشرة. لا توجد حسابات أو فواتير مسبقة.
3. أضف المستخدمين من شاشة الفريق: يُولَّد لكل مستخدم رمز مؤقت يسلّمه المدير يدويًا، ويُجبر المستخدم على تغييره عند أول دخول.
4. نسيان كلمة المرور: يطلبه الموظف والمدير يعيد ضبطه. القفل بعد 5 محاولات فاشلة.
5. المستندات: حسابي ثم "المستندات والملفات" لرفع وحفظ وتنزيل أي ملف (حد 25 ميجابايت للملف).

## 4) حدود يجب معرفتها (مهم)
هذه النسخة بلا خادم. كل البيانات والمستندات في متصفح الجهاز نفسه:
- لا مزامنة بين الأجهزة، والمستخدمون الذين تنشئهم موجودون على هذا الجهاز فقط.
- تسجيل الدخول حماية واجهة فقط، وليس أمنًا حقيقيًا: من يملك الجهاز ويعرف أدوات المطوّر يستطيع قراءة البيانات. لا تستخدمها لبيانات حساسة لأكثر من شخص.
- مسح بيانات المتصفح يحذف كل شيء. خذ نسخة احتياطية بانتظام.
- للاستخدام الفعلي متعدد المستخدمين تحتاج خادمًا (مخطط `db/` جاهز: PostgreSQL مع عزل الصفوف وسجل تدقيق).

## 5) تحديث الكود لاحقًا
عدّل الملفات ثم: `git add -A && git commit -m "وصف التعديل" && git push`. يعيد النشر نفسه خلال دقيقة، ويحدّث التطبيق المثبّت عند فتحه مرتين.
